# Current limitations

F98 follow-up in unreleased0.6 provides local lighting drafts and independent offline codecs only. Exact revision/interface selection, complete read/backup, acknowledgments and recovery remain unresolved; no physical F98 operation is enabled. The95 resource positions do not establish all physical keys. Per-key page encoders zero unrecovered slots and are not safe restoration images. Local random-color/direction/sleep settings and onboard macros remain incomplete. Older lighting-null profiles are migrated in memory and retained unchanged on disk until explicit save. See [F98 contract](F98_RESEARCH.md).

Real reviewed wired write paths exist for lighting, per-key colors, base/Fn assignments, sleep and scoped lighting/sleep restore. Their protocol/transaction code is tested offline and their read banks are physically verified; **the user has reported a successful physical theme change**. A scoped brightness6→5→6 test subsequently passed native readback and exact all-bank restoration. Other operations and persistence still need separate physical validation. Do not claim hardware success until an actual Apply returns matching readback, or persistence until a reconnection/power-cycle test.

Onboard macro uploads remain unavailable. The raw event/record/pool codec is evidence-backed, but hardware playback timing, exact capacity, repeat semantics, binding reconstruction and interrupted-upload recovery remain incomplete. Unreleased0.6 adds bounded local-millisecond to application-wire inspection after resolving after-event delay placement; it does not generate or transmit HID commands. Leading nonzero delays, unsupported usages/names and over-limit sequences reject conversion. Wireless configuration, debounce, OS layout, polling, firmware/revision queries, arbitrary shortcut editing, knob actions and firmware/reset operations are unavailable.

Only original ANSI geometry/mapping is currently implemented. Regional ISO and firmware revisions need independent evidence. Fn/F1–F12 source remapping is conservatively protected. The current editor/profile represents keyboard-page targets; five normal mouse-button actions and fourteen native Consumer actions are supported in both layer editors, including16-bit application-launch actions; their physical events remain unverified and compositor handling varies. Other Consumer/shortcut/vendor actions are not represented. Reading a bank omits unrepresentable vendor actions from the editable draft and retains them in raw backups.

Restoration is explicitly scoped: supported preset effect records, adjustable first palette colors and sleep. Unknown config bytes and other palette entries are preserved. Bank restoration is separately exposed for known ANSI source/LED entries (including Fn RGB); protected Fn/F input controls must match the backup and remain unchanged. Unknown positions are preserved, disabling a base key is rejected, and current lighting mode is preserved. This does not clone arbitrary full memory. Custom-mode snapshots use bank restoration rather than preset restoration. A before-restore backup is created. This is not a factory reset.

Effect previews are illustrative and not measurements of firmware animations. Direction controls remain unavailable. Native export uses WebKit downloads/text rather than an OS file chooser; copying JSON is a fallback. Preferences use XDG_CONFIG_HOME separately from profile data. No automatic history cleanup, encryption, cloud sync, app updater, AppImage or privileged service is supplied.

OS locks coordinate current app instances; unrelated configurators may ignore them. A blocked kernel IO can outlive the5s UI timeout, retaining its locks. Deadlines prevent subsequent operations after expiry, but a write whose syscall began before timeout may have reached hardware; errors therefore explicitly report uncertainty and do not retry/rollback.


The original UI is recreated from static resources, configuration and native constructor evidence, not a runtime capture of every screen in this exact Windows build. The optional private background/nav/wheel artwork matches those supplied files. Standalone graphics and the correct ANSI keyboard are independently drawn; the supplied package's French ISO key artwork cannot represent this ANSI device. Native dialogs, macro editor and unsupported controls differ. Pixel-perfect identity, font rasterization and every original screen are not claimed.

Old0.1–0.3 mapping/per-key artifacts contain an incorrect French-derived bottom-row role assignment. Use0.4+ only. The saved local bytes establish Fn53/RightCtrl59 roles, but physical LED correspondence and all write behavior remain unvalidated. Mismatching Fn marker layouts are now rejected before matrix operations.

## Multi-model expansion

The Device library provides working local editors, not physical compatibility for additional keyboards. Stable0.5 has no new-model hardware access. Unreleased0.6 adds only explicit identity-gated experimental reads for three F87 variants, F108 and H108; all new-model configuration writes remain disabled. No physical validation of these readers has occurred. Resource key counts/layouts may differ by revision; S99 conflicting indices remain unknown and F98 resource count95 is not physically reconciled. Several modes/layers/settings remain unrecovered. S75 packet codecs do not establish F108 Pro compatibility, channel semantics or a complete backup/restore/persistence flow. Its per-key read/write page counts differ. Onboard macro framing is partly understood, but timing/action/binding/limits remain insufficient for upload. F2088 static extraction is resolved in unreleased0.6; its partial103-position local workspace and offline eight-byte panel codec do not establish device access. Driver/host-versus-onboard behavior, full layout and safe read/backup/recovery remain incomplete. Mouse protocols also need further work. [Evidence and gaps](MULTI_MODEL_RESEARCH.md).
