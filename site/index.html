05 / YOUR SETTINGS

A deliberate
apply button.

Startup, reconnection and saving a profile leave the keyboard alone. Supported device changes follow an explicit review.

  1. 01

    Make a local draft.

    Edit a profile on your computer. Demo mode never configures a physical keyboard.

  2. 02

    Back up. Review.

    Check the device, affected settings and saved before-state before any supported write.

  3. 03

    Apply. Read back.

    Success requires matching readback. An uncertain result never triggers an automatic retry.

06 / BEFORE YOU INSTALL

A few things
worth knowing.

Does this fully replace the Windows software?

Not yet. Detailed UI parity and hardware coverage remain incomplete. Onboard macro upload, wireless configuration and some device settings are unavailable or under investigation.

Why are the Windows and Mac builds previews?

They use native desktop runtimes, but building an app is different from physically validating every USB operation. The download and installation notes identify unsigned packages and current platform limits.

Do I need Node, Rust, Wine or a browser?

Not for a packaged application. Node and Rust are build tools for source contributors. The app uses the operating system's webview; it does not require a browser configurator or Wine.

Is this on npm, AUR or Flathub?

No npm package, AUR listing or Flathub listing is published. Use the native downloads. A reviewed AUR recipe in the repository is not the same as a published package.

Can I try it without changing my keyboard?

Yes. Enter demo mode. Local profiles and macro preview do not configure hardware or inject input into other applications.

Can additional keyboards be supported?

Static analysis can recover layouts and formats from their software. Communication, device revisions and safe persistence still require physical validation. Read the model support policy before assuming compatibility.
